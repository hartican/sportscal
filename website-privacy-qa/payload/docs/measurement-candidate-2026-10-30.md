## First-party owner

`public/measurement.js` owns the consent state, local event lifetime, UI and standard browser SDK adapter. `measurement-start.js` intentionally ships with `sdkEnabled:false`. Neither a remembered Allow nor a URL marker can bypass that release gate. Other origins remain off. The current candidate must not be published as an enabled tracking release until the technical acceptance below passes.

The default is off. The small notice offers Allow and Decline, with a footer Privacy choices control for management/withdrawal. Only `{version:1,allowed:boolean}` is stored in the consent key. Missing, invalid or inaccessible storage, failed writes/readback and SDK errors fail closed. User actions while off are dropped, not queued for later grant. Withdrawal advances the generation before cleanup; a delayed old SDK completion cannot grant or send an application event. SDK cleanup exceptions cannot prevent persistence and the reload transition.

Allow first records consent, then navigates through the existing-origin `/privacy/reload` route. The handler returns a fixed303 destination, `Cache-Control:no-store` and `Referrer-Policy:no-referrer`; it never forwards incoming URL values. The fixed resume marker is removed with the normal History API before vendor code exists. The adapter separately requires canonical HTTPS origin, root path, no query/hash and a genuinely empty `document.referrer` before SDK loading. A failed clean transition does not loop. No document/referrer property, SDK internals or network API is replaced to pretend that metadata is clean.

Withdrawal calls the public consent revocation command, removes the owned script element and requests a fresh document. Every failed choice write uses the fixed `privacy=off` destination independently of SDK ownership, including a remembered Allow after SDK failure or while the release gate is off. Removing a script is not treated as cancellation of an issued request. Existing remote data, accepted requests and cookie history are not undone.

Website score preference remains in its existing key. A separate first-party, single-use session checkpoint restores public fixture filters, installer state, eligible open dialogs and scroll across the privacy transition, with a60-second expiry. It contains no incoming URL/referrer/contact data and is never passed as tracking parameters. A storage failure can prevent restoration of ephemeral UI state; this is not an account/Follow recovery mechanism.

The public SDK bootstrap queues initial revoke, autoConfig=false and init with the approved Pixel only. Manual calls use trackSingle(PageView) and trackSingleCustom(OpenApp) without custom parameters or user data. `autoConfig=false` is not represented as an all-metadata suppression control. Vendor browser identifiers/cookies, automatic metadata/events and asynchronous work remain subject to real SDK proof.

## Bounded remote browser handover

ROOT allocates the existing Linux QA service/window. No browser is launched on the source Mac. Transfer only the explicit file/hash manifest: landing HTML, first-party JS/CSS, redirect helper/route, original root response source, both validators and this record. Do not transfer the repository, dependencies, `.git`, credentials, profiles, runtime storage or customer data.

`scripts/verify-measurement-browser.cjs --verify-only --manifest=<manifest> --root=<payload>` verifies hashes without requiring Playwright or launching a browser. Browser mode is Linux-only and requires exactly one `--engine=chromium|webkit` profile and an absolute owned `--output` folder. Mock-SDK mode tests actual DOM/delegation/lifetime paths without allowing Meta requests. Actual mode additionally requires `--live-meta` and ROOT's exact `NS_META_QA_SOURCE`, `NS_META_QA_ORIGIN=https://nothingsport.com`, `NS_META_QA_PIXEL=1149008224326641`, and bounded `NS_META_QA_MAX_REQUESTS` (1–40).

The verifier fulfills the whitelisted first-party source on the scope-approved canonical domain in a new empty owned browser context. It never contacts the actual app or live feed. It uses an explicitly recorded QA-only bootstrap projection enabling the real controller; the published bootstrap stays off. That projection is not acceptance of an enabled production bootstrap. The real SDK profile expects exactly two PageView and two OpenApp event requests, plus a separately held real SDK asset response for withdrawal-before-execution. ROOT must review the request budget before granting that test window. An extra event, unexpected host, private query/referrer canary, unknown contact/custom/click-ID data, capture failure, post-withdrawal request or newly changed post-withdrawal cookie fails the check. Unknown SDK encodings fail rather than being silently omitted.

The report freezes initiation scope synchronously before header/document awaits. Later capture, forwarding decisions, response header events and actual `response.finished()`/failed settlement each have distinct observations; pending work is bounded and drained before and after cleanup. A pre-withdrawal request may complete afterward; that is retained distinctly. Supported event envelopes are scalar query, URL-encoded form and strict multipart form with explicit fields; JSON/batched/nested/unknown and duplicate fields are rejected before forwarding. Generic SDK source hashes are captured from the actual response. A held asset response is an explicit QA fault injection, not a claim about normal network timing.

Each browser invocation reserves a new output directory and writes an initial FAIL before manifest/tool/browser initialization. Existing attempts are refused without overwriting them. Execution, evidence settlement, browser cleanup and atomic final reporting have independent failure handling; the first error stays primary, and no failed attempt can become green through cleanup or retry. If final writing fails, the new attempt's initial FAIL remains. Raw request bodies belong only in owned QA evidence, never the application or visitor profiles.
