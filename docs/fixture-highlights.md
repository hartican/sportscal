# Fixture highlights

Approved 13–15 October 2026 (Australia/Sydney). Tennis is the first ingestion adapter; fixture metadata and the Watch highlights action are sport-neutral.

## Product rules

- Completed senior men's/women's singles and senior men's/women's/mixed doubles qualify at every round, including qualifying and round-robin individual matches. Junior/wheelchair draws, team ties and tournament overviews remain outside this individual-match adapter. Seven-day Feed cards qualify without changing existing follows or admission. A sourced round total is required to convert an ordinal round to a draw size; no universal Round 4 = Last 16 assumption.
- Verified official media requires reviewed rights-holder channel IDs; the separately approved automatic top search result may use any publisher. The initial registry covers ATP Tour, WTA, Tennis TV and the four Grand Slams. New channels need a reviewed official identity and competition scope.
- Use standalone match highlights with an exact edition/tournament, draw and participants binding. All four doubles players must match. Exclude Shorts, interviews, point clips and compilations. Titles/thumbnails never appear on the card.
- The YouTube mark and Watch highlights label are visible on fully minimised, summary and expanded cards, including Results OFF. A valid official record opens its canonical video directly. For completed named fixtures already in the seven-day Feed, the later 15 October approval opens YouTube’s own first relevance-search video automatically through the existing selected fixture route. The tooltip explicitly says the match is unverified. Identity, competition, sport, date/session and Tennis player/tournament/year queries retain their existing owner. Search selections grant no official-match or playback guarantee and never enter the verified media field. There is no results chooser. Verified links retain their own expiry/restriction rules; the recent fallback may select a different upload.
- Media does not create fixtures, grant Feed eligibility, change retention, alter sporting clocks, rate a fixture, enable alerts or change follows.

## Refresh ownership and fallbacks

`node scripts/update-cards.js` remains the only canonical owner. Full and quick refreshes include media discovery/projection. `node scripts/update-cards.js --highlights --local-only` is the scoped source/projection path. The existing protected live refresh has one `discovery-tennis-highlights` source, due every 30 minutes, behind current score work, with the existing leases/deadline/backoff. The media owner uses the existing two-read participant bundle for the complete Tennis sport family, including new roster/source arrivals, unknown rows and required published/archive aliases. It avoids a whole-world fixture projection while preserving the three-second database deadlines; it adds no RPC, query or scheduler. No new scheduler or browser polling loop exists. If the complete existing scoped input fails its unchanged deadline, discovery continues from published last-good fixtures and any returned last-good rows. Its report remains partial with inputState: published-fallback and the original sanitised input failure; this is not current-input recovery or complete source-only coverage.

Official public Atom feeds are the default. An approved feed supplies the video ID, publisher, publication date and normal-watch/Shorts link. Public oEmbed confirms video/publisher availability. These feeds expose a rolling recent-upload window; cached candidates retain 256 videos. This is not an exhaustive historical index. Seven-day cards are attempted first, then bounded archived references. Within each group, matches with the best known verified world ranking are checked first, followed by the other participant rank, newest date and deterministic ID; unknown rankings come last. Singles rankings do not invent doubles rankings. A six-hour per-match/channel historical-search cooldown lets the queue progress after higher-ranked pairs have been attempted; public feeds continue to detect new uploads every due pass. Optional `YOUTUBE_DATA_API_KEY` enables channel-upload fallback, batched video/region verification and at most two historical searches per due pass. API-only videos of three minutes or less remain pending when ordinary-video versus Shorts classification is unknown.

Public feeds/oEmbed do not expose territory restrictions. Their record uses `regionStatus: unknown`; no Australian playback guarantee is manufactured. API-confirmed Australian restrictions suppress the link and survive loss of the key. Deleted/private links are cleared after authoritative failure; transient failures retain the prior verified link. Existing links are rechecked daily. Metadata and availability expire after 30 days unless their provider checks succeed. `verifiedAt` keeps first provenance, `checkedAt` records a successful availability check, and `sourceCheckedAt` records a successful full metadata read. Check-only timestamps are already excluded from sporting revisions and card fingerprints. oEmbed alone cannot renew an old publication/description receipt; failed attempts and overall coverage timestamps never renew either bound. The existing owner emits explicit withdrawals for expired retained records, removes old candidate metadata and negative availability, and purges the canonical cache even in offline/failure projection. Readers hide expired cached actions. Unchanged sporting hashes leave stored fixture rows alone; the existing two-read transport projects renewed receipts only from matching, successful per-video checks in the owner’s saved private health document. A separate transport validator delivers those renewed dates to cached clients without a sporting revision or card-state change. Stale transport caches also withdraw expired media when database reads fail. No new database request, job or viewer-triggered write is added.

The sport-neutral `fixture-highlights.v1` record contains provider, video ID, exact canonical URL, approved channel ID, publisher publication date, verification date, public availability, region status, standalone flag and matching evidence. Video titles are retained for matching but never rendered. Optional `fixture.highlights: null` withdraws media explicitly. Backend source enrichment changes this field only and cannot create a missing fixture.

## Archives

The archive owner preserves source tournament/draw/round/participant metadata and highlights. The media source uses the archive owner's service-only `nothingsports_referenced_classics` and `nothingsports_hydrate_classic_highlights` RPCs. It pages 200 shared fixture references at a time, without account identity, and writes only changed media. A missing/not-yet-deployed archive schema is reported as pending and does not break recent discovery. Archive readers use stored media, with a read-only static-cache fallback for snapshots lacking the field. A stored record or explicit withdrawal always wins; viewer reads perform no media-provider request or enrichment write. Frozen editorial and ordinary Feed retirement remain archive-owned.

## Cost and activation

The public-feed path needs no API key. Expected YouTube API charge at this volume is A$0/month; even an API-first seven-channel/30-minute design is roughly 400–500 ordinary quota units daily, before historical searches. The sole shared live media owner caps historical search at two calls per pass and 90 calls per Pacific calendar day, below Google's separate 100-call daily search bucket. Ordinary API requests are capped at 500 units per Pacific day, below the default 10,000 ordinary units. All used endpoints cost one unit each. The existing private source-health report retains reservations made before every request, including provider errors and outer owner timeouts; regressed/malformed ledger state fails closed. Pacific DST and midnight resets are explicit. Canonical full/quick/scoped refresh remains public-feed/oEmbed only even if a key is configured, so it cannot create a second API ledger owner. Reaching either cap retains free provider discovery and existing cached selections; uncached top-result actions report unavailable until quota returns; it never increases spending or changes sporting facts. Premium is a viewing subscription and does not supply an API key or extra API quota. Hosting/database usage remains within the existing owners and is separate from YouTube API quota.
