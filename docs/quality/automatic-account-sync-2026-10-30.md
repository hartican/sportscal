## Narrow change

Remember at most one lifecycle availability event while the existing owner is busy, or while a failed attempt is within its15-second burst boundary. At that boundary, mark the witness eligible but retain it while the matching work is still busy. Consume it once only after actual settlement. Only current account/subject, SDK session generation, captured local profile, app-sync generation and error state may enter the existing recovery owner. Existing visibility/offline/session/recovery-hold gates still apply. A clean result needs no follow-up; an error without a new witness schedules none; a failed follow-up cannot loop. Replacing an obsolete witness clears its timer. There is no polling, second sync owner, forced PUT, receipt/base change or destructive recovery. The helper remains deferred. Window focus joins the same visible/coalesced lifecycle path; it is not a new sync owner. The existing account-render callback is only a notification, never settlement evidence. The original full async bootstrap body is observed through its complete promise, including metadata hydration and pending-intent reconciliation; the callback cannot consume a witness at intermediate signedIn. A matching full-promise finalizer releases the observation, and the owned lifecycle-job finalizer does the same for lifecycle work. This is ephemeral activity observation, not a new queue/serializer or persisted store. Obsolete/lifetime-ended witnesses clear their timers immediately.
