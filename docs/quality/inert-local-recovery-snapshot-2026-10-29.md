# Inert local recovery snapshot preparation

This is offline source preparation, not a supported phone export/restore feature. No page mounts it and no module runs on import. It neither reads a real phone nor writes local/server storage. Only synthetic fixtures were used. Physical598 sync acceptance remains FAILED; pending choices must remain intact.

## Explicit inputs and coverage

`collectSnapshot({readRam,readStorage}, expectedBinding)` requires caller-supplied synchronous adapters and account/profile/generation/shell/worker binding. It reads one supplied RAM object and exactly four known storage entries: install pointer, active-profile pointer, that active profile's raw JSON text, and the separate fixture-pin queue. No storage enumeration, loadActiveProfile, migration, savePreferences, session helper or network client is imported.

RAM fields are separately labelled: original preferences and active bundle, original pending receipt, accepted baseline, startup baseline, event/removal state, spoiler state, ratings, archive references, and pending fixture-pin queue. Raw persisted strings remain unchanged, including whitespace. RAM and persisted pin queues are not merged. The pending receipt remains original evidence; nothing acknowledges, rebases or replays it. Owner/profile/generation mismatches block capture. Other-owner receipt sets block rather than exporting another account's data.

The independent validator accepts a JSON envelope plus an independently supplied original RAM/storage reference. It validates format/coverage/bindings, compares exact JSON values and raw stored strings, and rejects tampering. Its result explicitly says restoreSafe:false, receiptReplayAllowed:false and freshServerBackedUp:false. JSON roundtrip equality is not validated import, account reauthentication, conflict resolution, or permission to recreate a baseline.

## Privacy and failure behavior

Known profile/preferences containers only are eligible. Unclassified preference roots and extra keys in top-level Follow/graph/tennis/FIFA containers block instead of being silently dropped. Classified nested choice data is preserved; credential field names and recognizable bearer/JWT/private-key/calendar/credential-URL patterns block. Uncertain URLs containing query/fragment credentials block conservatively. Non-JSON data, accessors, cycles, unsupported prototypes, nonfinite numbers, negative zero, holes and capacity overflow block rather than serialize lossily. Limits are64 nesting levels,200000 visited nodes,2million characters per string and8million UTF-8 bytes for parsed envelope/text.

These checks are conservative, not proof that arbitrary innocuously labelled free text cannot contain an undisclosed secret. A future actual adapter/source context still needs review and capture authorization. No blanket localStorage dump is supported. Unexpected adapter errors become fixed error codes without their message/cause. No backup data, field paths, values or identities are logged. Fixtures and sensitive sentinels in tests are entirely synthetic. A rejected capture produces no partial export.

Explicit omissions: auth/session credentials, fresh server snapshot, other profiles, cookies/caches/chat media/drafts, calendar secrets, OS push bindings, restore/rebase/replay/account reauthentication, and atomic cross-store/server capture. A null/unavailable source is not relabelled as a complete server backup. Separate source snapshots are evidence, not an atomic cloud/device transaction.

## Qualification

`node scripts/validate-inert-local-snapshot.js` is a finite synthetic-only test entry. It traps live window/document/localStorage access, freezes supplied in-memory originals, verifies allowlisted reads, explicit OFF/empty/exclusions/removals and both ON/OFF pending pins, raw text retention, independent-reference tamper rejection, owner/generation failures, unsupported choice blocking, credential sentinel rejection without output, adapter-error redaction and inert import. It never imports a restore/reset path or executes the saved receipt.

The first28-case run passed. Source inspection then added negative-zero/nonfinite/Date-object and uncertain-query-URL controls; the32-case run passed. Source reviews then identified unrecognised private/signing/service-role key fields and sparse arrays with expando properties; both were corrected with explicit own-index checks and credential controls. A44-case run passed, with additional session/auth-field and conservative profile-metadata controls prepared for final qualification. All runs used Node24.21.0 with deny-network/child/worker preload, each under30seconds and aggregate well under90seconds. Real phone capture and restore are untested and unallocated.

## Concrete continuation to a practical export (not implemented here)

1. Existing authenticated GET `/api/user-state` needs a narrowly named recovery-snapshot mode immediately after authenticatedUser and before the current GET Promise.all. Use only loadUserState for that authenticated subject; skip activePreferenceRecovery (its RPC may clean expired rows). Reject a row with mismatched owner, no body/query target UUID, no email/session/token/cookie projection. Return a versioned bounded whitelist of the raw own-row profile/preferences/actions/spoilers/ratings/archive/schema/update timestamp plus subject/provenance, private/no-store. Do not normalize/migrate/apply the row or manufacture a missing baseline. Synthetic handler controls must verify unauth/wrong-owner fail closed, one scoped read, zero RPC/write, credentials absent and legitimate choices retained.
2. An explicit Account export action, after its own source/runtime allocation, must run the reviewed local collector in the SAME installed instance. Use an explicit owner/generation adapter, never auth storage. Fetch that one existing authenticated snapshot mode, retain local and server data separately, and abort if binding/local choices change before validation/download. Do not auto-sync, savePreferences, accept a new baseline, ACK a receipt, or retry/capture repeatedly. Source-only preparation here does not add this action or consume a request.
3. Independently validate both source envelopes and the combined owner/version/time-labelled manifest before a user-owned local download. Check file readback independently on disposable memory. Do not send backup content to logs, Git, reports, chat, telemetry or an application upload. Unknown/credential-bearing content blocks with a clear non-identifying message. Existing bundle/budget constraints still apply to any later UI wiring.
4. No safe import/restore policy exists yet. A rehearsal must distinguish reproducing current visible choices from preserving original pending-intent evidence. Old receipts cannot simply be replayed or assigned a fresh server base; that could re-create this hold or overwrite newer choices. Manual pins/removals/OFF/empty, matching owner and future session generation must be explicitly qualified before any actual restore. Capturing a file is not sufficient permission to delete.

No phone instructions or deletion/reset/reinstall/storage clear/customer query is authorized by this source stage.
