# Repeated build checks — measured reduction without weaker gates

**13 October 2026 · published and verified live in shell 522**

The checked first clean module is published and deployed at `369907bf9fc6be86dfb2f286fe0334c7930ce1db`. [Normal release](https://github.com/hartican/sportscal/actions/runs/38347923232) passed. The separately approved smaller-card module follows later; no extra app deployment is needed for this report update.

The same source was being compressed again whenever a check asked for the card source. The existing compact-status check asks twice. A small change reuses the previous compression only inside the same Node process and only when the complete freshly assembled source is identical. Every call still reads the current inputs.

In a bounded local sample, the second and third builds took **3.157 seconds before and 0.227 seconds after**, about **92.8% less repeated work**. Generated app bytes are identical. The first build varied from 1921 to 2231 milliseconds; no cold-build, whole-release, browser, cash or token saving is claimed from this small sample.

## Acceptance and scope

- Reuse only the previous assembled-source/output pair in the current Node process. Add no persisted cache, service, dependency or scheduler.
- Assemble and read current inputs on every build. Any real source change must produce fresh output; source read and syntax failures must still fail. Failures cannot poison later successful checks.
- Keep the existing compression settings and generated bytes identical for unchanged inputs. Retain the normal exact source-to-runtime gate and startup limits.
- Verify changes, missing source, invalid syntax, stale generated output and restoration in an isolated disposable copy. Keep the user's actual source and data untouched by that test.
- Run the affected identity/timing checks and normal byte gate. Run `node scripts/validate-app-shell-build-cache.js` when changing this build tool; do not add another recurring owner routine.
- Combine with the existing checked release lane. Do not claim publication or deployment until its exact snapshot has passed normal gates.

The focused regression passes: repeated output, actual source invalidation, missing/invalid-source failures, stale-output rejection through the real `--check` command and normal recovery. Actual card identity and timing checks pass. Its initial disposable copy lacked the existing compiler dependency; the test now reuses the same installed compiler via a temporary link, without downloading anything. The initial setup failure is retained. The disposable folder is removed in `finally`.
