## Verified gaps and bounded repair

The previous loader trusted the provider's `numPages` value with no fixed request bound, and checked only total fixture/club/matchweek counts after fetching. Controlled responses made it attempt a fifth request; the test stopped it there, while the production code had no explicit cap. Other controlled complete responses with matchweek 39, a duplicate home/away pairing or the wrong season were accepted despite the existing counts passing. The unchanged published baseline reproduces those acceptances. No such corruption was found in the current real source.

The loader now validates page index, page size, total pages, total fixtures and expected page length before fetching another page. Four pages follow directly from the already agreed 380-fixture season and requested size of 100; this is not an arbitrary new competition limit. It checks the complete collection's EPL/season identifiers, positive unique fixture and club IDs, exactly two distinct clubs per fixture, matchweeks 1–38 and 380 distinct directed home/away pairings. Twenty clubs with all 380 unique non-self directed pairs establish one home and one away meeting per pair. It does not require ten fixtures per played week, infer dates or prohibit genuine reschedules.

Socket inactivity alone could leave a continuously active response pending indefinitely. The same 20-second duration is now also a fixed network deadline; response errors and incomplete aborted pages reject through the existing failure path. This bounds network waiting, rather than claiming a hard CPU/memory budget for arbitrary JSON. No retry or longer timeout is introduced. Completed-score validation and stable-ID/result continuity remain. Canonical refresh retains the existing delayed backup; the live source retains its shared last-good failure behaviour without adding a live backup path.
