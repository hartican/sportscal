# Match Centre: less unnecessary data, complete current matches — 12 October 2026

**Status: locally checked; independent review, publication and live application pending.** The app remains shell 516. No new subscription or owner routine.

Match Centre was loading many calendars and old results that could never appear on its current screen. That makes it easier to hit the existing waiting limit and show a degraded list. This repair selects possible current matches first, then reads only their needed source observations. It keeps correction information, current scores and original dates. The shared display rules remain authoritative.

## Evidence and outcome

Production logs show the same three-second fixture-bundle timeout before that repair at 11:20 UTC and afterward at 11:39 UTC. Reconstructed with independent fact/verification dates in local PostgreSQL and evaluated at 13:02 UTC, the final replacement compares 1,294 to 109 rows and 3,159,957 to 289,720 compact JSON bytes, about 91% less transfer. The actual shared source overlay and model return identical complete match objects: all five eligible matches, same order, names, participants, venues, scores and original clocks. Every retained projected row is identical. The reconstruction is separately labelled because the actual raw fixture/score split was not exported, and the old reader's future window changes with evaluation time.

A read-only inline trial of the final proposed query on live PostgreSQL 17 at 13:02 UTC returned 151 complete rows /436,129 text bytes in 1,278.254 ms under a 2.5-second diagnostic deadline. Different observation times, source activity and text/compact encoding mean these are not controlled causal latency comparisons. No application function was replaced or provider refresh forced for that measurement. Cold/concurrent/hosted and physical-device performance remain unproven.

A final actual-overlay probe caught a pre-release draft dropping a separate source's team names and venue when only the score row independently qualified. The final query keeps connected declared identities (including transitive aliases), equivalent source starts and nonempty uncertain clocks before projecting receipts. Conservative same-start context does not create a match relationship; the unchanged JS merger determines that. Two focused regressions reproduce identity-chain and different-ID semantic merges and compare complete old/new match objects. The faulty draft was never applied live.
