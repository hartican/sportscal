The existing F1 result loader now uses a private invocation budget when it owns
the transport. This is neither another refresh entrypoint nor an allocation to
run it. The canonical owner remains `update-cards.js --f1-results --local-only`.

Derive at most five selected session paths from existing canonical identities,
the unchanged seven-day window and practice's ninety-minute delay. Read the
exact official 2026 index first; only its explicit GP hrefs can authorize those
selected paths. No guessed numeric GP identity, redirect, retry or extra session
is permitted. Reuse each downloaded resource within the invocation.

The HTTPS reader checks fifteen seconds over each complete resource including
headers, body, decompression, strict UTF8 decoding and synchronous source-table
parsing. Wire and decoded bodies each have a one-MiB resource cap and six-MiB
invocation cap. There are at most six GETs. A monotonic 120-second source budget
is checked before and after owned work. Failures cancel active readers; the
owner closes the budget in `finally`. The existing constructed parser tests
retain their injected reader; the default production reader uses these limits.

The existing F1 regression invokes the bounded-reader controls once. An actual
loader negative supplies an oversized owned response: the frozen base accepts
it without a source-size rejection, whereas this slice rejects it. Compression,
strict decode, redirects, malformed/incomplete bodies, memoization, exact selected
scope, body stalls and parse clocks have separate controlled cases. These are
constructed transport inputs, not raw official HTML captures or provider proof.
