## Separate local startup interruption

A concurrent wider run stopped at the unchanged ten-second startup wait, before main navigation/preferences or the deferred repaired module existed. The parser was still loading and had encountered only the two first critical scripts. No timeout, retry or source gate was relaxed. The final unchanged-source 60-case run was executed separately with temporary observer-only tracing; all 220 server and 228 browser critical-asset observations finished, with maxima of 3 ms and 42 ms respectively and no failed/unfinished entries.

**Inferred:** competing local browser/check work may have contributed. **Unverified:** the exact cause of the earlier stall is not captured, and the successful isolated run does not prove it fixed. Preserve the failure and keep local browser acceptance sequential; if it recurs, capture the same three-asset timing seam before changing startup code. The trace only observes public paths/times and changes no responses or deadlines. The previous saved-team delivery recorded a separate earlier startup timeout; both remain historical evidence.
