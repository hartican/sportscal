## Recovery

Private prior_preferences and prior_updated_at are retained in private.nothingsports_horse_flagship_cohort. Recovery is operator-reviewed and transactional, never a login-time default. For each cohort row, take the same erasure advisory barrier and reread the current state FOR UPDATE. Skip erased/blocked accounts and any state whose updated_at differs from applied_updated_at: later user edits must never be overwritten. For unchanged existing rows only, restore prior_preferences with a fresh monotonically increased updated_at. For unchanged rows created by this rollout only, remove the newly created state if all other state columns remain their original defaults. Retain the completed run marker so recovery/retries cannot recapture future accounts or re-enable later unfollows. Report skipped rows as recovery requiring review, not a failed reset to be forced. No recovery SQL is executed automatically.
